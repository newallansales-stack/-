# 免费历史文章报价

本次根据“先尽量收集免费公开数据”的要求，新增 IT之家公开新闻日历和文章商品卡片整理。没有购买数据、申请付费账户或绕过登录、验证码。

数据位于 [historical-prices.json](../datasets/historical-prices.json)，网站“历史文章报价”页可筛选品类、年份、报价类型，搜索型号，查看日/周/月柱，并下载完整 CSV/JSON。观察报价的 [public-prices.json](../datasets/public-prices.json) 仍然独立，不将两种日期和价格口径混合。

## 日期到底代表什么

- `publicationDate` / `publishedAt`：原始文章在 `#pubtime_baidu` 标示的北京时间。日历条目与文章日期不一致时不采纳价格。
- `observedAt`：本次实际读取网页的时间。现在找回一篇 2020 年文章，不声称自己在 2020 年抓取过它。
- `effectiveDate=null`：通常不知道报价实际生效日，也没有成交依据。例如 2020-01-09 的年货节文章中，有一条长芯 720GB SSD 的 299 元卡片明确写“1 月 10 日 10:00 开始”。保留该条件，记录在文章日期，不能解释为 1 月 9 日已经可以买到。
- 图表按**文章发布日期**汇总同一来源规格、同一报价类型的金额。空白日期、整周没有文章记录时均留空。它不是连续的市场成交 K 线，更不是“从 2020 年每天都有数据”。

网页现在读取的原文可能曾经被作者更新，新闻发布时间也不能证明内容自那天起完全未变；这种来源限制保留在数据口径中。若需证明某日真实可购或成交，仍须更强的当时存档、订单或授权历史库。

## 免费来源如何查找

1. 从公开日历 `https://www.ithome.com/list/YYYY-MM-DD.html` 读取带日期的原始新闻标题与链接。首批检查覆盖 2020 年全部自然日及后来年份部分日期；网页动态显示已检查日历数与实际有报价的日期数。**检查了某天的新闻，不等于取得了那天所有商品价格。**
2. 从候选文章的正文 `#paragraph` 内读取商品卡片。只接受京东、天猫、淘宝、拼多多卡片中的明确人民币单件 / 单套金额；记录原始名称、卡片说明、原文标题、链接、报价文字与相关促销说明。
3. 相关资讯、推荐文章、广告侧栏中的卡片不当作该文章的证据。没有带日期正文、没有有效商品卡片的文章不生成价格记录。
4. 海外美元换算、约数、最低起价、多规格选项、定金、分期单期金额、单位折算价及硬件整机 / 主板组合包不填成单个配件价格。具体筛选由测试约束。
5. 原文明确提供 `data-jdid` 时保留标准京东 SKU 链接；没有明确 SKU 时不解析或猜测联盟签名。SKU 链接也未经过商家实时直核。

新闻日历与正文独立检查。GitHub 上发现的采集程序、示例数据仍不能替代历史数据库；没有把标记为模拟的金额收入本档案。

## 型号与条件

数据保留原卡片的完整型号文本和说明。未知频率、CL、内存条数、显存、盒装/散片保持未知，不能按类似型号填入。明确京东 SKU 的记录，只有可识别的容量以及内存代际、频率、条数、CL、CPU 包装等规格标记一致时才聚合；未知值不填成明确值。促销营销文字不作为规格，原型号与卡片说明仍逐条保留。没有明确 SKU 的不同文章不自动认作同一商品。

`quoteType=promotion` 为卡片或标题明确提到优惠券、补贴、到手价、促销等的金额；其余为 `reported_listing`（文章标示售价）。类型分别统计，不与站点参考价或当前转引报价混算最低价。具体优惠可能只适用于原文中的某件商品；`articleContext` 是相关原文说明，不能自动断言每项优惠都适用于每个规格。

所有记录均标示：

```text
currency=CNY
dateBasis=article_publication
verification=published_article_only
availability=historical_unknown
effectiveDate=null
```

这些值不能改名为“已验证在售”“实际成交”或“全网最低”。

## 持续免费回补

```bash
npm run collect:history
# 只继续读取现有候选文章，不新增日历扫描：
node --use-env-proxy --use-system-ca scripts/collect-history.mjs --articles-only
```

默认每次扫描最多 60 个日历页，优先检查最近两天的新文章，再从 2020 年起继续尚未检查的旧日期；读取最多 100 篇尚未处理的候选文章。检查进度保存在 [history-index.json](../datasets/history-index.json)，报价与处理结果保存在历史档案中。它是可恢复的增量回补，不需要让用户自己寻找 CSV。

GitHub Pages 的每日北京时间 09:15 计划任务同时运行公开观察报价采集和免费历史文章回补，保存仓库后测试、构建、发布。GitHub 计划可能延迟，站点结构变化或限流会影响进度；HTTP 429 时停止该轮来源访问，不解验证码或更换出口规避限制。普通代码推送只发布已有档案。人工也可运行工作流并勾选 `refresh_prices`。

记录缺口仍在：新闻网站并不每天报道每款硬件，没有报道或未找到证据的日期不会产生报价。扩大免费文章的覆盖范围可以补充历史线索，无法据此保证重建每个中国零售 SKU 从 2020 年起每天的价格。
